# Security model

GitHub Pages is public and static. It never receives the Supabase service-role key, payment secrets or webhook secrets.

## Controls

- Supabase RLS is enabled on every application table.
- Browser writes are limited by user ownership policies.
- Admin-only verification and moderation is enforced by database policy.
- Input validation belongs at both the UI boundary and Edge Function boundary.
- Product downloads must be generated by a privileged function and expire quickly.
- Product archives should be stored privately and never in the public bucket.
- Payment state is changed only after a verified provider webhook.
- Audit events are recorded for security-sensitive moderation/account operations.
- Do not accept archives without size/type limits and decompression safeguards.
- Never execute uploaded source code as part of verification.

## Threat boundaries

A successful build check does not prove that a package is safe. A dependency scan does not prove originality. A seller identity does not prove copyright ownership. These distinctions are intentionally visible in the trust UI.
